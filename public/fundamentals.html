Part I

Foundations

Everything built later — transformers, language models, agents — rests on a handful of ideas that predate all of them. A model is a function fitted to data; learning is the search for its parameters; and the whole discipline of measuring one honestly exists because a model that looks perfect usually isn't.

What Is Machine Learning?

Key idea

Instead of writing the rule, you write a program that finds the rule from examples.

Machine learning is a way of building software that improves at a task by learning from data, rather than following rules a programmer wrote by hand. Instead of coding "if X then Y" for every case, you show the program many examples and let it find the pattern connecting the input to the output.

The result is a model: a function, fitted to data, that can make a prediction or decision on new examples it hasn't seen before. What varies between methods is the shape of that function — a straight line, a tree of yes/no questions, a stack of matrix multiplications — and how its adjustable numbers, called parameters, are chosen.

The inputs are features: the measurable properties you hand the model, such as the sender of an email, the number of links in it, and the hour it arrived. The known answer attached to a training example is its label. Much of the practical work in machine learning is not choosing the algorithm but choosing and cleaning the features, because a model can only find patterns in what it is shown.

Supervised, Unsupervised, and Reinforcement Learning

Key idea

What a model can learn is decided by what kind of feedback it gets: the right answer, no answer, or a score.

Supervised learning trains on labeled examples — each input comes with the correct answer attached, such as an email marked "spam" or "not spam." The model learns to map inputs to those known outputs. It splits into classification, where the answer is one of a fixed set of categories, and regression, where the answer is a number.

Unsupervised learning works on unlabeled data. There's no correct answer given; instead, the model finds structure on its own, such as grouping similar customers together (clustering), compressing many correlated features into a few (dimensionality reduction), or flagging points that don't look like the rest (anomaly detection).

Reinforcement learning learns by trial and error inside an environment, receiving rewards or penalties for its actions. Rather than learning from a fixed dataset, it learns a strategy — a policy — by acting, observing the outcome, and adjusting. It is the approach behind game-playing systems and robotics control, and, in modified form, behind the preference tuning that turns a raw language model into a usable assistant.

A fourth term worth knowing: self-supervised learning, where labels are generated from the data itself — hide part of a sentence and ask the model to predict it. There is no annotation cost, so it can consume enormous corpora. This is how modern language models are trained, and it is the reason they exist at the scale they do.

How a Model Actually Learns

Key idea

Training is a search: measure how wrong the model is, work out which direction reduces that error, take a small step, repeat.

"Learning" sounds vague until you see the mechanism, which is the same one in almost every method that involves fitting parameters. It has three parts.

First, a loss function turns the model's wrongness into a single number. For regression that is often mean squared error, the average of the squared gaps between prediction and truth. For classification it is usually cross-entropy, which punishes a model for being confidently wrong far more than for being uncertain. The loss is the definition of "good" that the model will optimise, so choosing it badly is a way of solving the wrong problem precisely.

Second, the gradient tells you which way is downhill. It is the derivative of the loss with respect to each parameter — the answer to "if I nudge this one number up slightly, does the error grow or shrink, and how fast?"

Third, gradient descent takes the step. Every parameter moves a little in the direction that reduces loss, scaled by a learning rate. Too large a rate and training bounces around or diverges; too small and it crawls. In practice the gradient is computed on a small random batch of examples rather than the whole dataset — stochastic gradient descent — and one pass over the data is called an epoch.

That loop, run millions of times, is what "training" means, whether the model has three parameters or three hundred billion.

The Train/Test Split

Key idea

A score on data the model has already seen is not a score, it is a memory test.

A model that's only ever evaluated on the data it was trained on will look better than it really is — it can memorize answers instead of learning general patterns. To catch this, the available data is split: most of it (the training set) is used to fit the model, and a held-out portion (the test set) is used only to measure how well it performs on examples it never saw during training.

A common split is 80% training, 20% testing, though the right ratio depends on how much data is available. Serious projects carve out a third slice, the validation set, used to tune choices such as the learning rate or the model size — because every time you look at a score and change something in response, you leak a little information from that data into the model. The test set is spent the moment you start optimising against it, so it is kept sealed until the end.

When data is scarce, cross-validation gets more out of it: split the data into k folds, train k times, each time holding out a different fold, and average the scores.

Overfitting

Key idea

A model powerful enough to learn the pattern is also powerful enough to memorise the noise.

Overfitting happens when a model learns the training data too well — including its noise and quirks — rather than the general pattern underneath. An overfit model scores extremely well on training data but performs poorly on new, unseen data, because it memorized specifics instead of learning something that generalizes.

The train/test split exists specifically to detect this: a big gap between training accuracy and test accuracy is the classic sign. The opposite failure, underfitting, is a model too simple to capture the pattern at all — it scores badly on both sets. Between them sits the bias–variance trade-off, the reason model selection is a balance rather than a maximisation.

The standard defences are all forms of "make it harder to memorise": collect more data, simplify the model, add a regularisation penalty on large parameter values, stop training early when the validation score turns, or — in neural networks — randomly switch off units during training so no single one can carry a memorised answer.

Measuring a Model Honestly

Key idea

Accuracy is the metric that lies most often, because it treats every kind of mistake as the same mistake.

Consider a fraud detector on a dataset where one transaction in a thousand is fraudulent. A model that answers "not fraud" every single time is 99.9% accurate and completely worthless. To see that, you need to separate the kinds of error, which is what a confusion matrix does: it counts the four possible combinations of what was true and what was predicted.

From those four counts come the metrics that actually matter:

  • Precision — of everything the model flagged, how much was right: TP / (TP + FP). Low precision means false alarms.
  • Recall — of everything it should have flagged, how much it caught: TP / (TP + FN). Low recall means misses.
  • F1 — the harmonic mean of the two, for when you need one number and both errors matter.

Precision and recall trade against each other: move the decision threshold to catch more real cases and you will also flag more innocent ones. Which way to lean is a domain question, not a modelling one. A cancer screen should tolerate false alarms to avoid misses; a spam filter should do the opposite, because a lost job offer costs more than a junk mail in the inbox.

Common Algorithms

Key idea

A handful of model shapes cover most classical problems, and the boring ones win more often than people expect.

A few algorithms show up across most introductions to the field:

  • Linear regression — predicts a continuous number by fitting a straight-line relationship between inputs and output. Fast, and its coefficients can be read as an explanation.
  • Logistic regression — despite the name, used for classification: it squashes a linear score through a sigmoid to produce a probability between 0 and 1.
  • Decision trees — make predictions by asking a sequence of yes/no questions about the input, each one chosen to separate the data as cleanly as possible.
  • Random forests and gradient boosting — hundreds of trees combined, each correcting the others. On ordinary tabular data these remain the strongest thing to reach for, and they routinely beat neural networks on it.
  • k-means clustering — an unsupervised method that groups data points into a chosen number of clusters by repeatedly assigning each point to the nearest cluster centre and recomputing the centres.
  • Neural networks — layers of simple connected units that combine to approximate complex, non-linear relationships. They dominate where the input is unstructured — images, audio, text — which is exactly where the rest of this guide goes next.
